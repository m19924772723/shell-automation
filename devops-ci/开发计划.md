# DevOps 与 CI/CD · 开发计划

> 原则：**每个阶段都产出可运行、可验证的东西**，先小步跑通再逐步加深。

## 阶段一 · 容器化

- **目标**：跑通
- **产出**：可运行的镜像

- [ ] 写 Dockerfile
- [ ] 本地构建运行
- [ ] compose 编排

## 阶段二 · CI

- **目标**：自动
- **产出**：自动构建测试

- [ ] 写 workflow
- [ ] 自动测试
- [ ] 构建产物

## 阶段三 · CD

- **目标**：自动发布
- **产出**：自动部署流水线

- [ ] 镜像推送
- [ ] 部署脚本
- [ ] tag 触发

## 阶段四 · 运维

- **目标**：可交付
- **产出**：可回滚的发布体系

- [ ] 密钥管理
- [ ] 灰度与回滚
- [ ] 监控告警

---

### 里程碑与验收

| 阶段 | 验收标准 |
|---|---|
| 阶段一 · 容器化 | 可运行的镜像 |
| 阶段二 · CI | 自动构建测试 |
| 阶段三 · CD | 自动部署流水线 |
| 阶段四 · 运维 | 可回滚的发布体系 |

> 建议：每完成一个阶段就在本目录下建一个具体项目子目录，把成果固化下来。
